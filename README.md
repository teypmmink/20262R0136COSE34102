## 프로세스와 스레드

프로세스는 실행 중인 프로그램의 인스턴스로, 주소 공간과 운영체제가 관리하는 자원을 갖습니다.
스레드는 프로세스 안의 실행 흐름이며, 같은 프로세스의 스레드들은 코드·데이터·힙을 공유합니다.
각 스레드는 자신만의 레지스터 상태와 스택을 가집니다.

프로세스는 실행 상태에 따라 준비, 실행, 대기 상태 등을 오갑니다.
문맥 교환은 현재 실행 흐름의 상태를 저장하고 다음 실행 흐름의 상태를 복원하는 과정입니다.
문맥 교환에도 비용이 발생하므로 전환 횟수만 늘린다고 성능이 좋아지지는 않습니다.

## CPU 스케줄링

CPU 스케줄러는 준비 상태의 실행 대상 중 다음에 CPU를 사용할 대상을 선택합니다.

- FCFS: 먼저 도착한 작업부터 실행합니다. 긴 작업 뒤의 짧은 작업이 오래 기다릴 수 있습니다.
- SJF: 예상 CPU 실행 시간이 짧은 작업을 우선합니다. 실행 시간 예측이 필요하며 긴 작업이 밀릴 수 있습니다.
- Round Robin: 시간 할당량마다 실행 기회를 나눕니다. 할당량이 너무 작으면 문맥 교환 부담이 커집니다.
- 우선순위 스케줄링: 우선순위에 따라 선택합니다. 낮은 우선순위 작업의 기아를 완화하기 위해 에이징을 사용할 수 있습니다.

반환 시간은 도착부터 완료까지, 응답 시간은 도착부터 첫 실행까지의 시간입니다.
대기 시간은 준비 큐에서 기다린 시간의 합이며, 처리량은 단위 시간에 완료한 작업 수입니다.

## 동기화와 임계 구역

여러 실행 흐름이 공유 데이터를 동기화 없이 수정하면 실행 순서에 따라 결과가 달라지는 경쟁 상태가 발생할 수 있습니다.
예를 들어 값을 읽고 1을 더한 뒤 저장하는 연산은 여러 단계이므로, 두 스레드의 갱신 중 하나가 사라질 수 있습니다.

임계 구역은 공유 자원에 접근하는 코드 구간입니다. 상호 배제는 동시에 하나의 실행 흐름만 그 구간에 들어가도록 제한합니다.
뮤텍스는 잠금 소유권을 통해 접근을 보호하며, 세마포어는 카운터를 이용해 접근 수나 실행 순서를 조절할 수 있습니다.

조건 변수는 공유 상태가 특정 조건을 만족할 때까지 대기하는 데 사용합니다.
대기에서 깨어나도 조건이 유지된다는 보장은 없으므로, 잠금을 다시 확보한 상태에서 조건을 반복 검사해야 합니다.

## 교착 상태

교착 상태는 실행 흐름들이 서로가 가진 자원을 기다리며 진행하지 못하는 상황입니다.
예를 들어 한 스레드가 A 잠금을 가진 채 B를 기다리고, 다른 스레드가 B를 가진 채 A를 기다리면 진행이 멈출 수 있습니다.

교착 상태가 발생하려면 다음 네 조건이 모두 성립해야 합니다.

1. 상호 배제: 자원을 동시에 사용할 수 없습니다.
2. 점유와 대기: 자원을 가진 상태에서 다른 자원을 기다립니다.
3. 비선점: 자원을 강제로 회수할 수 없습니다.
4. 순환 대기: 자원 대기 관계가 고리를 이룹니다.

모든 실행 흐름이 잠금을 같은 순서로 획득하도록 하면 순환 대기를 방지할 수 있습니다.
예방은 조건 자체를 깨는 방법이고, 회피는 자원 할당 후에도 안전 상태를 유지하도록 판단하는 방법입니다.
탐지와 복구는 교착 상태를 찾은 뒤 실행 흐름 종료나 자원 회수 등으로 해소하는 접근입니다.

## 메모리 관리와 주소 변환

가상 주소는 프로그램이 사용하는 주소이며, 물리 주소는 실제 메모리의 위치를 가리킵니다.
페이징은 가상 주소 공간을 고정 크기 페이지로, 물리 메모리를 같은 크기의 프레임으로 나눕니다.
페이지 테이블은 가상 페이지와 물리 프레임의 대응 및 접근 권한 등을 기록합니다.

가상 주소의 페이지 번호로 매핑을 찾고, 페이지 내부의 오프셋을 유지하여 물리 주소를 구성합니다.
TLB는 최근 주소 변환 결과를 캐시해 페이지 테이블 조회 비용을 줄입니다.
TLB 미스는 변환 정보가 캐시에 없다는 뜻이며, 페이지가 메모리에 없다는 뜻과는 다릅니다.

페이징은 연속 프레임 할당이 필요 없어 외부 단편화 문제를 줄이지만, 마지막 페이지 등에 내부 단편화가 생길 수 있습니다.
